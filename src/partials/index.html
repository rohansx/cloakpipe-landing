The production problem

Your API can be healthy
while your agent is wrong.

Agent behavior changes when a prompt, model snapshot, tool schema, MCP server, retrieval index, permission, or policy changes. Conventional monitoring sees successful HTTP calls. CloakPipe tracks the complete behavior-affecting release and connects pre-production assurance to runtime authority.

Configuration drift

The production agent no longer matches the configuration that passed evaluation.

Silent regression

The model still responds, but tool choice, schema adherence, task completion, latency, or cost degrades.

Unbounded authority

A prompt injection or changed tool grants the model more authority than its certified release received.

Unverifiable logs

A mutable dashboard cannot independently prove which configuration ran or why an action was allowed.

The control loop

From change
to verified decision.

Explore the architecture →

CloakPipe does not replace your evaluation platform, gateway, telemetry, or CI system. It binds their evidence to one Agent Release, applies a deterministic decision, enforces it, and records the result. Every step below is in the open-source core or the cloud today.

01 · EVALUATE
Release assurance
Test the exact agent configuration—not an isolated prompt or model.
  • cloakpipe eval import reads JUnit XML, Braintrust experiments, and Langfuse dataset runs
  • Fail closed: an unscored case is an error, never a pass
  • release diff maps each changed component to the suites it requires
02 · CERTIFY
Signed certification
Turn results into a deterministic, reproducible release decision.
  • Rules for critical failures, pass-rate regression against a baseline, coverage, and metrics
  • Ed25519-signed DSSE certification bound to the manifest hash
  • Offline verify-cert, revocation statements, and a GitHub Action
03 · ENFORCE
Runtime control
Only certified releases receive production authority.
  • Cedar sees the release; revoked releases are blocked and uncertified ones stay pseudonymized
  • Production promotion requires a valid certification or a recorded break-glass reason
  • Sentinels revoke on live error, block, or deny rates; the MCP gate allows only declared tools
04 · PROVE
Portable evidence
Verify the basis and outcome of a decision outside the dashboard.
  • Hash-chained, Ed25519-signed ledger records bound to the release hash
  • PII types, policy decisions, and tool hops; never raw values
  • Offline verifier for ledger bundles and certifications

Building next

Not claimed
