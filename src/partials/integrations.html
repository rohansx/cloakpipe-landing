Route to any model.

How the proxy routes →

The proxy is OpenAI-compatible and provider-agnostic. Point your app at a CloakPipe endpoint and route to closed models, managed clouds, or self-hosted weights. Different masking policies per provider — strict for closed models, lighter or bypassed for models inside your own perimeter.

04 · Agent protocols

CloakPipe as
a tool.

MCP tool gate docs →

The native Model Context Protocol server exposes CloakPipe's core operations as agent tools, and cloakpipe mcp-proxy sits in front of any upstream MCP server as a gate. Every call lands in the signed ledger.

pseudonymize & rehydrate tools

pseudonymize replaces sensitive entities with consistent tokens and rehydrate restores the real values — vault-backed, the same entity always maps to the same token.

detect tool

detect finds sensitive entities in text without replacing them, returning category, confidence and source for each match.

configure & session tools

configure switches the industry profile or detection categories at runtime, session_context inspects context-aware sessions, and vault_stats reports vault mappings.

Claude Desktop · Cursor · any MCP client

Drop the server into Claude Desktop, Cursor, or any MCP-compatible runtime. Through mcp-proxy, PII in tool-call arguments is pseudonymized and tokens in results are rehydrated under policy.

MCP tool gate

cloakpipe mcp-proxy --manifest --certification allows only the tools a certified release declares; a refused call gets JSON-RPC -32001, and anything the gate cannot parse is refused, never forwarded. Docs →

Release-bound hops

Every tool call through the gate is recorded in the hash-chained, signed ledger with the release hash, so an auditor can see which certified release called which tool.

05 · Evaluation & CI

Keep your evals.
Certify the release.

Release control →

CloakPipe does not replace your evaluation tool. cloakpipe eval import turns its results into a native EvaluationRun bound to the release hash, and scoring fails closed: an unscored case is an error, and a case passes only when every score meets the threshold.

JUnit XML

Any test runner that writes JUnit XML, such as pytest or Jest, becomes certification evidence. Mark critical cases by id pattern.

Braintrust

Import experiment events fetched from the Braintrust API. Choose which scores count; a case missing a named score is an error.

Langfuse

Import a Langfuse dataset run and its scores, fetched from the Langfuse API, with the same pass threshold and fail-closed rules.

GitHub Action

Run certification in CI. The Action returns certified or blocked for the candidate release and, given a signing key, signs the decision.

CloakPipe Cloud: upload the same JUnit, Braintrust, or Langfuse results from CI or the dashboard, and the server converts them with the same importer. Docs

06 · Key management

You hold
the keys.

How the vault works →

The vault encrypts every real value with AES-256 using local keys today. Bring-your-own-key through your existing KMS is on the roadmap, with envelope encryption and rotation. None of the adapters below is available yet.

AWS KMS · planned

Customer-managed keys in AWS KMS via envelope encryption. Keys rotate on your schedule; existing tokens stay decryptable.

GCP Cloud KMS · planned

Root keys in Google Cloud KMS. Per-tenant vault namespaces mean no cross-tenant access is possible at the cryptographic level.

Azure Key Vault · planned

Manage encryption keys in Azure Key Vault. Automatic rotation runs without disrupting active tokens.

HashiCorp Vault Transit · planned

Use Vault Transit as the key-management backend for BYOK envelope encryption across self-hosted and air-gapped deployments.
